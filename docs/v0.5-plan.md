**Budget:** no fixed number for this release (user, 22 November 2026): keep it lean.

## Decisions (user, 22 November 2026)

| # | Choice | Why |
|---|---|---|
| 1 | SQLite driver: `ncruces/go-sqlite3`, its direct API (not `database/sql`) | Pure Go, so `CGO_ENABLED=0` builds stay. | 2 | An `Engine` interface; Postgres stays in `db.go`, SQLite goes in `sqlite.go` | A second engine is here, so the interface is now worth having |
| 3 | SQLite gets full parity, editing included | Same opt-in, same review-and-apply, same conflict rules |
| 4 | `engine` and `path` fields on a connection; the dialog switches between Postgres and SQLite | A SQLite file has one database, `main`, with one schema, `main` |
| 5 | Keychain first; if the keychain fails, the password stays in the 0600 file and a warning is logged | Nothing breaks on Linux without a Secret Service. Whether to refuse there instead is deferred |

## Scope

1. **Passwords in the OS keychain** (macOS Keychain, Windows Credential Manager, Linux Secret Service) through `zalando/go-keyring`: service `open-tableplus`, account = connection ID.
   - `Put` stores the password in the keychain and writes it out of `connections.json`. `Delete` removes it.
   - When the app loads, plaintext passwords already in the file are moved into the keychain.
   - Passwords are read from the keychain when a pool is opened or a connection is tested, and never reach the UI.
   - On macOS, `go-keyring` writes through `security -i` on stdin, so the password isn't in `ps`. The item belongs to `/usr/bin/security`, so rebuilt (unsigned) binaries don't prompt.
2. **SQLite connections.** Name, file path, environment label, and "Allow editing". Browse, quick search, filters, sort, paging, SQL tab, history, CSV export, structure view, and editing all work as they do for Postgres.

## Read-only and the one writer, for SQLite

- Every request opens the file with `SQLITE_OPEN_READONLY`, so SQLite refuses writes, including to attached files (they inherit the flag). Each request runs inside `BEGIN … ROLLBACK` and closes the connection afterwards, so nothing carries over between requests.
- User SQL is prepared once. If SQLite reports any SQL left after the first statement, the request is refused, so multi-statement strings are rejected without our code parsing SQL.
- Only `Edit` opens the file read-write, in `BEGIN IMMEDIATE … COMMIT`, running statements it builds itself, and only when the connection has `editable` set.
- Cancelling the request or hitting the 30s timeout interrupts the query (`SetInterrupt`).

## Shared SQL building

The table-view SELECT (search, filters, sort) and the edit statements are built once for both engines. The two differences are a dialect value: the parameter prefix (`$1` or `?1`) and the case-insensitive match (`ILIKE` or `LIKE`). Both engines run `CAST(x AS TEXT)`, `LIKE … ESCAPE '\'` and `IS NOT DISTINCT FROM`. Filter values are untyped parameters, so the database takes their type from the column (no `$1::type` cast).

## Values

Values stay as the database's own text or null. SQLite integers, reals and text come back as SQLite prints them. Blobs show as `\x` plus hex, like Postgres `bytea`. Column types are the declared types (empty for expressions).

## Out of scope

SSH/TLS tunnels; deciding the Linux no-keychain behaviour; creating new SQLite files from the UI; `ATTACH`.

## Done when

- A new connection's password is in the keychain and not in `connections.json`. An existing plaintext password moves into the keychain when the app loads. Deleting the connection removes the keychain item. Tests use `keyring.MockInit()`.
- With the keychain failing, saving still works and the password stays in the 0600 file.
- On a SQLite fixture, these work and are covered by tests: tree, rows with search/filters/sort/paging, exact values (integer, real, text, blob, null, date text), SQL tab results and errors, a multi-statement string refused, a write from the SQL tab refused, export, structure, and editing (apply, all-or-nothing, conflict, and opt-in refused).
- `go vet`, `go test -race` and `scripts/release.sh` (all five targets, `CGO_ENABLED=0`) pass.
- README, `docs/STATUS.md` and this file are current.
